# Ревьюер ответов книги

Заполняет `book_problems.correct_answer` для заданий с `answer_source='none'`,
решая их напрямую (собственным рассуждением в этой сессии — по подписке
Claude Code, без отдельного Anthropic API ключа и без DeepSeek). Точечная
онлайн-генерация (кнопка «Ответ ИИ» в UI, DeepSeek) и этот скил — два разных,
независимых пути к одному результату (`answer_source='ai'`); скил замещает
только массовую офлайн-обработку целой книги.

## Когда использовать

Пользователь просит «прогони книгу X», «сгенерируй ответы для [учебника]»,
«добавь ответы там где их нет» — для книги, уже лежащей в `books`/
`book_problems` (импортированной через `scripts/book-import.mjs`).

## Пошагово

### 1. Найти книгу

Если передан явный `book_id` (uuid) — использовать как есть. Если передано
название/предмет/класс, найти через Supabase MCP (`execute_sql`):

```sql
select id, title, subject, grade, level
from books
where title ilike '%<кусок названия>%'
order by created_at desc;
```

Несколько совпадений — показать список, уточнить у пользователя. Ничего не
найдено — сказать явно, не выдумывать книгу.

### 2. Собрать задания без ответа

```sql
select id, task_number, task_number_sort, prompt_md, has_images, options
from book_problems
where book_id = '<book_id>'
  and answer_source = 'none'
  and correct_answer is null
  and is_active = true
order by task_number_sort nulls last;
```

Разделить результат: `has_images = true` → сразу в «пропущено (картинки)»,
дальше не трогать (текстовый ревью их не решает — как и online-путь). Дать
пользователю сводку: всего без ответа / пропущено картинок / в работу.

Если «в работу» пусто — сообщить и остановиться.

### 3. Прогреться на выборке (первые ~10)

Решить первые ~10 заданий из очереди (см. «Как решать» ниже), показать
пользователю таблицу «№ → ответ → метод», спросить, продолжать ли на всю
книгу — так же, как раньше `--dry-run` в скрипте. Если пользователь уже явно
попросил «прогони всю книгу без остановки» — можно пропустить этот чек-пойнт.

### 4. Обработать очередь батчами

Держать прогресс в TodoWrite (по одной задаче на батч ~20-30 заданий — книга
на 300+ заданий иначе не влезет в разумный отчёт и легко потерять место).

**Для батча ≤20 заданий** — решать последовательно самому в этом же потоке
рассуждения.

**Для книги целиком (сотни заданий)** — параллелить через Agent
(`subagent_type: general-purpose`, несколько батчей в одном сообщении
одновременно, см. правила использования Agent tool). В промпте каждому
агенту передать: контекст книги (`title`/`subject`/`grade`), сам батч
(`id`, `task_number`, `prompt_md`, `options`), и ЭТИ ЖЕ инструкции по решению
и записи (агент — не онлайн-API, а такой же Claude Code, значит тоже решает
рассуждением и тоже имеет доступ к Supabase MCP и Bash для
`classify-answer.mjs`). Попросить агента вернуть краткую сводку
(решено/пропущено/низкая уверенность) — не пересказ каждого задания.

### 5. Как решать одно задание

1. Прочитать `prompt_md` (может содержать LaTeX `$...$`/`$$...$$` — не
   мешает пониманию условия).
2. Решить как обычную школьную задачу (5–11 класс, ОГЭ/ЕГЭ/ВПР). Дать только
   итоговый ответ, без хода решения:
   - подпункты «а) б) в)» → ответ в формате `а) …; б) …; в) …`;
   - дроби — десятичной дробью или `a/b`, без LaTeX в самом ответе;
   - варианты ответа (если есть `options`) — номер/буква правильного.
3. **Если не уверен** (задание требует рисунка/построения/измерения по
   графику, условие нечитаемо после OCR, двусмысленно, или ты правда не
   знаешь ответ) — **пропустить**, не гадать. Гадание портит авто-проверку
   учеников по этому эталону.
4. Классифицировать метод проверки — вызвать (Bash), не подбирать вручную:
   ```sh
   echo '{"promptMd": <JSON-строка prompt_md>, "answerText": "<решённый ответ>"}' \
     | node scripts/classify-answer.mjs
   ```
   Вернёт `{cleanedAnswer, gradingMethod, answerFormatHint}` — использовать
   `cleanedAnswer`/`gradingMethod` для записи (шаг 6). Это тот же код, что
   применяется к online-генерации и парсингу PDF — не дублировать логику
   вручную в уме.

### 6. Записать результат

Через Supabase MCP `execute_sql`, **условным** UPDATE (страховка от гонки,
если кто-то параллельно поставил ответ вручную/через UI):

```sql
update book_problems
set correct_answer = jsonb_build_object('text', '<cleanedAnswer, экранировать кавычки>'),
    grading_method = '<gradingMethod>',
    answer_source = 'ai',
    updated_at = now()
where id = '<problem_id>'
  and answer_source = 'none';
```

Проверить `rowCount`/затронутые строки — 0 означает гонку (кто-то уже
ответил), не ошибка, просто пропустить в отчёте. Можно батчить несколько
UPDATE в одном вызове `execute_sql` через `;` — SELECT-и так батчить нельзя
(возвращается только последний результат), но для UPDATE это не важно.

### 7. Итоговый отчёт

По завершении (или после каждого батча, если книга большая и требует
нескольких сообщений/дней): решено / пропущено (картинки) / пропущено
(неуверенность) / гонки. Напомнить пользователю: **выборочно сверить 5-10
ответов с ответами в конце бумажной книги** перед тем как полагаться на них
для авто-проверки учеников — это ИИ-эталон, а не сверенный факт.

## Ограничения

- Не трогает `library_problems` (это только для `book_problems` — библиотека
  ФИПИ/sdamgia размечается по-другому и online-путём через
  `/api/library/problems/[id]/ai-answer`).
- Не трогает задания с картинками (`has_images=true`) — текстовый ревью их
  не видит; для них остаётся online-путь через UI (кнопка «Ответ ИИ» тоже их
  пропускает) либо ручной ввод учителем.
- Не создаёт `task_answer_keys` — это происходит позже, при добавлении
  задания в тест (`add-to-test`), которое уже само подхватывает
  `book_problems.correct_answer`, если он есть на момент добавления.
