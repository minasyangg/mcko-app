# Импорт OCR-книг: полный пайплайн

Инструкция для модели (или разработчика), которая будет парсить новые
OCR-источники и развивать `scripts/book-import.mjs`. Здесь зафиксировано,
**как** и **почему** мы парсим каждый тип книги. Прочти целиком, прежде чем
трогать импортёр или добавлять новый источник.

## 0. Архитектура модуля

```
PDF → PaddleOCR (PP-StructureV3 или VL) → JSON (локально, в git НЕ коммитить!)
       → scripts/book-import.mjs (локальный CLI, service-role ключ)
       → Supabase: books / book_sections / book_pages / book_problems
       → интерактивная читалка /teacher/books (Next.js), задания-«атомы»
         в рамках с кнопками: ⊕ в тест, ✏ редактировать, 🗑 удалить, + создать
```

Принципы (см. AGENTS.md «Правила проекта»):
- **сайт только читает** — вся запись идёт локальным скриптом или серверными
  роутами через service role после проверки владельца/admin;
- **вёрстку книги не воспроизводим дословно** — упрощаем до читаемого KaTeX;
- **JSON в БД не хранится** — только распарсенные структуры.

## 1. Входной формат

Оба пайплайна PaddleOCR (PP-StructureV3 и VL-1.6) дают одинаковую форму —
массив страниц:

```jsonc
[{
  "prunedResult": { "parsing_res_list": [
    { "block_label": "text|paragraph_title|content|number|image|display_formula|table|…",
      "block_content": "…" }
  ]},
  "markdown": { "text": "…страница в markdown…", "images": { "imgs/xxx.jpg": "https://…bcebos…" } },
  "inputImage": "https://…"   // скан страницы (обложка книги = inputImage[0])
}, …]
```

Что берём:
- `markdown.text` — основной текст страницы (хранится в `book_pages.markdown`);
- `block_label: "number"` — печатный номер страницы → карта printed→scan
  (фолбэк: интерполяция от ближайшей известной, `printedToScan`);
- `block_label: "content"` — строки печатного оглавления;
- `markdown.images` — подстановка подписанных URL в `<img src>`
  (пока указывают на Baidu bcebos; перелив в Supabase Storage — план).

## 2. Нормализация markdown страницы (до всякого парсинга)

Порядок: `unwrapMathTasks → inlineShortDisplayMath → chainNormalizeMarkers → rewriteImages`.

1. **Распутывание LaTeX-обёрток** (`unwrapMathTaskLine`): OCR заворачивает
   целые строки заданий в `$$\circ\mathbf{12.2.a)}\begin{cases}…\end{cases}$$`.
   Снимаем `\mathbf/\mathrm/…`, `$$`, спейсинг-макросы; `\circ`→○, `\infty`→∞;
   номер и маркеры подпунктов выносим текстом, математические сегменты
   заворачиваем обратно в `$…$`. Строки-продолжения без номера, но с
   маркерами (`$$\mathbf{6})…\qquad\mathbf{r})…$$`) — та же распаковка
   (`unwrapMathMarkerLine`).
2. **Короткий display → inline** (`inlineShortDisplayMath`): `$$…$$` короче
   ~110 символов без `\begin`/`\\` → `$…$`, чтобы не растягивать строку
   и не порождать горизонтальный скролл.
3. **Маркеры подпунктов** (`chainNormalizeMarkers`): OCR путает кириллицу
   в «а) б) в) г)»: `a→а, 6→б, b→б|в, B→б|в, c/s/v→в, r/Γ/g→г, d→г|д, e/f→е`.
   Одна и та же латинская буква в разных книгах значит разное, поэтому решает
   **кластер + метод исключения**: маркеры одного задания собираются в кластер
   (начинается только с «а», разрыв >600 символов или >6 маркеров = новый),
   однозначные символы фиксируются (6→б, r→г), неоднозначные получают
   оставшиеся буквы кластера. Это корректно обрабатывает **двухколоночную
   вёрстку** (печатный порядок а) в) / б) г) — OCR читает а,в,б,г).
4. Ловушка JS: **`\b` не работает с кириллицей** (`[а-яё] ∉ \w`) — границы
   слов задавать только `(?![а-яё])`.

## 3. Оглавление (book_sections)

Два источника структуры:

- **Печатное оглавление** — `content`-блоки (могут быть в начале книги или
  в конце). `parseToc` понимает: `«Глава N»` отдельной строкой с заголовком
  на следующей (Макарычев) и `«Глава N. ЗАГОЛОВОК»` в одну строку (Мордкович);
  `§ N. Название ..... стр`; пункты `N. Название ..... стр`; «Домашняя
  контрольная работа №N» → kind `extra` под главой; переносы строк заголовков
  склеиваются (pending-логика). OCR-каша `«Για να δ.»` = «Глава».
- **Заголовки страниц** (дидактика, когда печатного TOC нет — Кубышева):
  h1/h2-строки → корневые части; заголовки работ («Самостоятельная/
  Контрольная/Проверочная работа …», «K-N (…)») → дочерние секции.

`page_start` секции — из printed→scan карты либо напрямую скан заголовка;
`page_end` — начало следующей секции − 1. Читалка грузит страницы диапазона
секции и рисует рамки заданий по якорям.

## 4. Типы источников и схемы нумерации

Автодетект: composite-совпадений ≥100 → composite; иначе plain.
`--type didactic` включает дидактический разбор явно.

### 4.1 Учебник, сквозная нумерация (plain) — Макарычев, Виленкин

- Задания: `^(глиф?)(N)(звёздочка?)\.` в начале строки. Глиф перед номером:
  ∞/⑤ = повышенная сложность, кружок «есть ответ» OCR-ится как `o/O/0/о/О`.
  `3*.` — звёздочка после номера = повышенная сложность.
- **Отбор номеров — LIS** (длиннейшая возрастающая подпоследовательность),
  НЕ монотонное окно: LIS сам выбрасывает OCR-галлюцинации («1260. Exposure
  to bpapacine.» между 1238 и 1239 убивала 16 заданий), дубли и рестарты
  «Контрольных вопросов».
- `task_number` = «735», sort = номер.

### 4.2 Задачник, нумерация по параграфам (composite) — Мордкович

- Задания `«5.30.»` = §5 задание 30. Фильтр монотонный: тот же § и +≤40,
  либо § +1..3 и номер ≤40.
- **«Итоговое повторение»** — глава со своей сквозной нумерацией 1..N:
  отдельный LIS-поток, sort = 1_000_000 + N; ответы к нему в блоке
  «ГЛАВА <номер главы повторения>» раздела ответов.
- **ДКР** («Домашняя контрольная работа №N», варианты 1-2, задания 1..10):
  зона от заголовка ДКР (fuzzy: «ДОМАЛИНЯЯ…») до конца секции;
  `task_number = к{дкр}.{вариант}.{номер}`.

### 4.3 Учебник, номер без знака препинания (bare) — Петерсон

Третья сквозная схема наряду с plain/composite: номер напечатан вообще без
точки/скобки — «23 Выполни действия:» (только пробел перед заглавной буквой,
формулой `$`, кавычкой «« или скобкой). Перед номером бывает буква-категория
задания (Петерсон: К=классная, П=повторение, Д=домашняя, С=смекалка; OCR
путает с латиницей K/D/C и греческой π), отделённая пробелом — не путать с
глифом-символом других схем (○/∞/⑤), который прилегает к номеру вплотную.

- Автодетект: `bareTotal >= 50 && bareTotal > dotTotal * 3` → scheme='bare'.
  Единый `SEQ_RE` (=BARE_RE при bare, иначе PLAIN_RE) используется во всех
  местах, где раньше был жёстко зашит PLAIN_RE (детект, next-page lookahead).
  Обрабатывается идентично 'plain' (тот же LIS-поток), отличается только
  извлекающий регэксп.
- **OCR рендерит открывашку задания как markdown-заголовок** («## 65 Найди…»,
  т.к. в PDF номер набран крупным шрифтом) — глобальная нормализация
  `demoteHeadingTaskNumbers` снимает `#{1,6}` с ЛЮБОЙ строки книги (не только
  bare-схемы), если остаток строки похож на открытие задания (bare или с
  точкой/скобкой). Без этого fix теряется ~10–15% заданий именно у Петерсона;
  попутно подобрал несколько десятков пропущенных заданий и в уже
  отгруженных Макарычеве/Виленкине (не регресс — чистый прирост, проверено
  дифом счётчиков и что «без раздела» осталось 0).
- **Печатное оглавление без номера страницы у «§ N. Title.»** (в отличие от
  Мордковича, где у § есть своя строка с отточием): `parseToc` открывает
  параграф сразу по бare-заголовку («§ N. Title.» без «.....N»), page_start
  параграфа остаётся `null` (нет своей страницы — чистый группирующий узел),
  punkt-дети внутри получают реальные страницы из своих строк как обычно.
- **Раздел «Ответы» без заголовка в оглавлении**: ответы просто дописаны в
  конец книги (сами используют дот-стиль «23. a) 0,02; 6) 46,47.» даже когда
  тело книги — bare!). Эвристика `findHeuristicAnswersStart`: с конца книги
  ищем последнюю страницу с плотным списком «N. значение» (≥6 совпадений
  лукбихайнд-регэкспа парсера ответов) и БЕЗ картинок (тело книги почти
  всегда содержит иллюстрацию-разделитель, ответы — никогда); окно
  расширяется назад, пока плотность держится ≥3 и картинок нет. Гейт
  `!isDidactic` — уже отгруженные дидактические сборники не имеют ответов
  вовсе, эвристика для них не запускается (нет риска регресса).
- Категория-глиф С/C («смекалка») трактуется как признак `difficulty=advanced`
  наравне с ∞/⑤.
- **Генерализация редактирования**: `computeAnchors` (lib/books/anchors.ts),
  `stripTaskNumber` (BookReader.tsx) и `headRe`-реконструкция (PATCH
  problems/[id]/route.ts) научены понимать bare-формат — терминатор после
  номера необязателен (`[.)]?` вместо обязательного), глиф — либо символ
  вплотную, либо буква-категория через пробел. PATCH сохраняет ОРИГИНАЛЬНЫЙ
  терминатор задания при пересборке текста после правки (не навязывает точку
  bare-заданиям).

### 4.5 Дидактика (didactic) — Чесноков-Нешков, Кубышева

Класс «работы × варианты», нумерация рестартует повсюду. Разбор —
конечный автомат по событиям страницы (в порядке позиций в markdown):

- **Заголовок работы** (`WORK_RE`: «Самостоятельная/Контрольная/Проверочная
  работа…» ед. число; `KR_HEAD_RE`: «K-N (пометка)», бывает БЕЗ `#`) →
  текущая работа. Повторные заголовки той же работы над каждым вариантом
  («K-1 …» ×4) **схлопываются** (same title в пределах 6 страниц);
  чередование серий (К-2 Виленкин / К-2 Нурк / К-2 Виленкин) возвращает
  к существующей работе. Коллизии печатных номеров (две серии К-1..)
  разрешаются сдвигом на следующий свободный номер вида.
- **Заголовок варианта** (`VARIANT_RE`: «Вариант N» + OCR-искажения
  «Бармант/Вармонят/Бермант/Варимят», допускается «ВАРИАНТ 1.») → вариант,
  сброс счётчика. Фолбэк: рестарт нумерации (1-2 после ≥3) = новый вариант.
- **Вариантные зоны** (Чесноков): секции печатного TOC «Вариант N» с большим
  диапазоном страниц — внутри сквозная нумерация 1..~350 на весь вариант;
  отдельный LIS-поток на вариант; `task_number = в{N}.{номер}`. Вход в зону
  сбрасывает текущую работу.
- Кандидаты до первой работы (предисловие, поурочное планирование) —
  не задания, отбрасываются.
- **Два стиля нумерации заданий**: «1.» (точка) и «1)» (скобка — Кубышева,
  5 класс; звёздочка бывает с обеих сторон скобки: «6)*»). Стиль фиксируется
  первым заданием варианта (styleLock): цифровые подпункты другого стиля
  внутри задания не плодят ложных атомов. В якорях скобочные кандидаты
  участвуют только в позиционном сопоставлении зонных номеров.
- `task_number = {с|р|п}{номер работы}.{вариант}.{номер}`.

### 4.6 Зонные номера: сводка

| формат   | значение                     | бейдж в UI            | sort                                |
|----------|------------------------------|-----------------------|-------------------------------------|
| `735`    | сквозной                     | «№ 735»               | 735                                 |
| `5.30`   | §5 задание 30                | «№ 5.30»              | 5030                                |
| `78`+rep | повторение                   | «№ 78»                | 1_000_078                           |
| `к1.2.3` | ДКР 1, вар. 2, № 3           | «ДКР 1 · вар. 2 · № 3»| 2M + дкр·10k + вар·1k + №           |
| `с5.2.3` | СР 5, вар. 2, № 3            | «СР 5 · вар. 2 · № 3» | 2M + globalIdx·10k + вар·1k + №     |
| `р2.1.4` | КР 2, вар. 1, № 4            | «КР 2 · вар. 1 · № 4» | —//—                                |
| `п3.1.2` | ПР 3, вар. 1, № 2            | «ПР 3 · вар. 1 · № 2» | —//—                                |
| `в2.157` | вариант 2, № 157 (сквозная)  | «вар. 2 · № 157»      | 10M + вар·100k + №                  |

В тексте книги напечатан только **видимый номер** (последний компонент) —
см. `visibleTaskNumber`/`taskNumberLabel` в `lib/books/anchors.ts`.

Bare-схема (Петерсон) хранит `task_number` в том же простом виде `735`, что
и plain — различается только регэксп-детектор при импорте/пересчёте якорей,
формат номера и бейдж («№ 735») те же.

## 5. Ответы (раздел «Ответы»)

1. Диапазон: секция `/^ответы/i` из TOC → до следующей секции книги.
2. Нормализация (`normalizeAnswersOcr`): распутывание `$$\mathbf{…}$$`-каши,
   спейсинг-макросов; строки «К параграфу N.» (латинская K!) вычищаются.
3. Кандидаты номеров: composite — `(N)[.,](M)[.,]` (запятые вместо точек,
   потерянные пробелы «3.33.353»); plain — `(N)\.(?=\s|\d)`.
4. **LIS** по номерам — ложные позиции из чисел внутри самих ответов
   выпадают. Значение = текст до следующего принятого номера (лимит 800).
5. Маркеры в значении — `chainNormalizeMarkers` («a) 35; 6) 22,5» → «а) … б) …»).
6. Эвристика автопроверки: ≤24 символов без подпунктов → `numeric_tolerance`
   (число) или `normalized`; иначе `manual`. Источник — `book_answers`.
7. У дидактики ответов обычно нет — счётчик 0 это норма.

## 6. Якоря (привязка рамок к тексту)

`book_problems.md_start/md_end` — смещения в `book_pages.markdown`.

Инварианты (нарушение = рамки сливаются/пропадают):
- диапазон задания **включает** хвостовой разделитель `\n\n` до следующего
  задания; любой серверный splice обязан сохранить перенос;
- в начале якоря стоит видимый номер задания в начале строки;
- пересчёт якорей после ЛЮБОЙ правки страницы — `computeAnchors`
  (`lib/books/anchors.ts`): сквозные номера ищутся по значению (первое
  вхождение), **зонные — позиционно** (видимые номера повторяются между
  вариантами!) в порядке `task_number_sort` (передавай `sortHint`).
- Номер задания пользователю не показывается в тексте (только бейдж)
  и не редактируется: клиент шлёт текст без номера, сервер восстанавливает
  `{глиф}{видимый номер}. ` сам.

## 7. Запись в БД и CLI

```bash
node scripts/book-import.mjs <файл.json> --dry-run          # отчёт без записи
node scripts/book-import.mjs <файл.json> --emit-sql <dir>   # SQL-файлы
SUPABASE_URL=https://<proj>.supabase.co node scripts/book-import.mjs <файл.json> \
  --replace \                       # удалить прежний импорт (по title+subject)
  --title "…" --authors "…" --subject "Математика" --grade 7 \
  --level "базовый|углублённый" --type textbook|problem_book|workbook|didactic \
  --publisher "…" --year 2013 \
  --created-by <uuid>               # ВАЖНО: аккаунт, под которым работает учитель
                                    # (иначе не увидит кнопки редактирования)
```

Ключ — `SUPABASE_SERVICE_ROLE_KEY` из `.env.import.local` (gitignored).
`--replace` каскадно удаляет прежние sections/pages/problems, **включая
ручные правки учителя** — предупреждай пользователя.

## 8. Верификация после импорта (чек-лист)

1. `--dry-run`: оглавление визуально соответствует книге; счётчик заданий
   ≈ последний номер книги (покрытие ≥90%); предупреждений немного и они
   объяснимы (OCR-потери).
2. Спот-чек 3-5 заданий разных типов (обычное, с подпунктами, зонное)
   и 2-3 ответов — сверить буквы подпунктов с книгой.
3. После записи: `book_problems` — `md_start IS NULL` = 0; каждый якорь
   начинается с видимого номера; рамки не пересекаются (сортировка спанов).
4. Открыть книгу на dev-стенде: рамки, поиск по номеру, ⊕ в тест.

## 9. Известные ограничения / что делать при новом источнике

- Номера, полностью потерянные OCR (ушли в картинку), не восстанавливаются —
  учитель досоздаёт вручную (кнопка «+» у разделителя страницы).
- ~1-2% строк остаются с LaTeX-кашей → правятся карандашом (KaTeX-превью).
- Картинки указывают на Baidu bcebos URL — протухнут; план: перелив в Storage.
- Новый источник: сначала `--dry-run` как есть → смотри, какой из типов
  (4.1-4.3) ближе; чаще всего хватает мета-флагов. Если структура нового
  класса — добавляй новую зонную модель по образцу didactic (события
  страницы → конечный автомат → LIS/монотонность → зонные task_number),
  и НЕ забудь: `visibleTaskNumber`/`taskNumberLabel`/`computeAnchors`
  в `lib/books/anchors.ts` должны понимать новый формат номера.
- Регрессия обязательна: `--dry-run` всех прежних книг. Счётчики МОГУТ расти
  при доработке общих (не источник-специфичных) частей пайплайна — например,
  `demoteHeadingTaskNumbers` подобрал ранее пропущенные задания сразу в
  нескольких книгах; в этом случае прирост — норма, а не регресс, если
  «без раздела» остаётся 0 и предупреждения объяснимы. Настоящий регресс —
  это ПАДЕНИЕ счётчика или рост «без раздела»/дублей. Актуальные эталоны
  (2026-07-08): Макарычев 1400/558, Мордкович 1522/608, Виленкин 1540/353,
  Чесноков 1812, Кубышева 754, Петерсон ч.1/2/3 — 281/368/472 заданий,
  109/87/105 ответов (найдены эвристикой — печатного заголовка «Ответы»
  в этих книгах нет вовсе).
